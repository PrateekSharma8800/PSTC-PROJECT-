# eVote – Online Voting and Election Management System

All voting logic is written in **C (C99)** and compiled to **WebAssembly** with Emscripten.
The web page (HTML/CSS/JavaScript) only shows the interface and calls the C functions.

## Folder structure
```
frontend/index.html        dashboard layout
frontend/css/style.css     navy/white theme, responsive
frontend/js/app.js         UI only – calls C through Module.cwrap
frontend/assets/           favicon
backend/voting.h           structures, constants, status codes, prototypes
backend/voting.c           global data, admin, election control, cast vote, messages
backend/voter.c            voter registration (18+), linear search
backend/candidate.c        candidate registration, duplicate check, linear search
backend/results.c          counting, maximum finding, winner, tie detection
backend/main.c             menu-driven console version (gcc only)
wasm/voting.js             generated by emcc (glue code)
wasm/voting.wasm           generated by emcc (compiled C)
build.sh                   builds both versions
```

## Build and run
```bash
brew install emscripten          # one time
./build.sh                       # builds voting_console + wasm/voting.js/.wasm

./voting_console                 # console version

python3 -m http.server 8000      # run from the project folder
# open http://localhost:8000/frontend/   (double-clicking index.html will NOT work)
```
Admin PIN: **1234** (change `ADMIN_PIN` in `backend/voting.h`).

## How C talks to JavaScript
1. Functions in `backend/*.c` are marked `EXPORT` (`EMSCRIPTEN_KEEPALIVE`) so emcc keeps them.
2. `emcc` compiles the four logic files (not `main.c`) into `wasm/voting.wasm` and generates the loader `wasm/voting.js`.
3. `app.js` wraps each function: `Module.cwrap("register_voter", "number", ["string", "number"])`.
4. C returns a positive ID or a negative status code; `get_status_message(code)` (a `switch`) gives the text.
5. Lists are read one item at a time by index, e.g. `get_candidate_name(i)`.

## Where the syllabus concepts are used
| Concept | Function |
|---|---|
| Structures, arrays of structures | `struct Voter voters[]`, `struct Candidate candidates[]` |
| Age verification (18+) | `register_voter` |
| Unique IDs | counters `nextVoterId` (1001…), `nextCandidateId` (101…) |
| Linear search | `find_voter`, `find_candidate`, `find_candidate_by_name` |
| Duplicate-vote prevention | `can_vote` / `cast_vote` check `hasVoted` |
| Live counting | `cast_vote` increments `votes`; `get_total_votes` loops |
| Maximum finding + tie detection | `get_max_votes`, `get_tie_count`, `get_winner_index` |
| switch-case | `get_status_message`, `get_state_name`, console menu |

## Election stages
`Not Started` (admin adds candidates, min. 2) → `Voting Open` → `Closed` (winner declared).
Voters can register in the first two stages.

## Limitations
- Data is saved per browser: `app.js` stores the list of successful actions in `localStorage`
  and replays them through the C functions on page load. Different devices don't share data.
- That saved list includes the admin PIN as typed, so this is a demo, not a secure system.
- No real authentication; anyone at the computer can use the voting screen.
- Fixed limits: 100 voters, 20 candidates, names up to 49 characters.
- After changing any C code, run `./build.sh` again.
